# Versions- und Releaseablauf

Laufende Änderungen werden auf `main` committet und nach GitHub übertragen. Sie erhalten erst eine Versionsnummer, wenn der Projektinhaber den Stand ausdrücklich als Release bezeichnet.

Die erste freigegebene Version heißt **0.5**, der Git-Tag **`v0.5`**. Jede weitere freigegebene Version erhöht sich um 0.1, also 0.6, 0.7 und so weiter. Der GitHub Release verweist auf den freigegebenen Commit und beschreibt die Änderungen seit dem letzten Release.

Öffentliche Beispielscreenshots dürfen das Spiel und die aktive Aufstellung zeigen. Vor der Veröffentlichung auf Spielernamen, Kontodaten, Geräteadressen und Zugangsdaten prüfen. Private Laufzeitdaten und Sicherungen bleiben außerhalb des öffentlichen Repositorys.

## Release workflow in English

Commit ongoing work to `main` and push it to GitHub. Assign a version only when the project owner explicitly designates a commit for release. Start with version **0.5** and tag **`v0.5`**, then increment by 0.1 for each approved release. Review public screenshots for private information. Gameplay and active lineups may be shown.
